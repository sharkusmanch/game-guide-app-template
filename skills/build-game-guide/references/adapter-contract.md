# Adapter contract form

The starter owns common browser acquisition/state; `src/game/adapter.ts` owns named game/profile validation, decoding and objectives. A game may extend the model deliberately with tests; do not manufacture a universal planner.

| Contract | Game-specific implementation and acceptance artifact |
|---|---|
| Input | Bytes plus exact supported edition/core/profile; signature/container/checksum/slot validation; size bounds; unsupported-file result |
| Decoder output | Derived facts with per-field evidence/unknowns; decoder/schema versions; capture and observation times; selected slot; source kind; identity assignment; safe digest if useful |
| Domain | Inventory/recipes/reservations or registration/held instances/ownership history as appropriate; checkpoint history cannot be inferred from a current save |
| Progress | Separate feed identity/set IDs, strict award IDs and hardcore timestamps; unavailable/stale/error states; no browser account keys |
| Fixture oracle | Link evidence-matrix rows; constructed/edited/other-core/target-core distinction; independent expected-value origin; missing fixture tests explicitly skipped |
| Shared transport regression | GET/no-store; total deadline through body; cancellation settles when fetch ignores AbortSignal; redirects/HTML/oversize rejection; source/attempt/revision races cannot commit; manual upload disables remote reads |
| Shared persistence regression | Game/version namespace; future/unreadable existing value preserved byte-for-byte with raw recovery download; validate restore before mutation; exports exclude raw save bytes; local backups retain configured `source.url` with remote reads disabled, so private backups stay outside public artifacts; URL sanitization is an additional per-game policy requiring implementation/tests; reversible new attempt clears active source/snapshot/history |
| Source adapter | Fixed-file or deterministic latest-validated-slot policy; directory replacement/partial-write tests; input read-only, browser-supported save/slot bytes atomically replaced; normalized bytes require an implemented profile; last good source and any separately implemented freshness/status contract |

Private source recipe: open a bounded stable snapshot read-only, validate through the same decoder/profile used by the browser, then write the selected original save/slot bytes into a temporary output in the destination filesystem and atomically rename it. `/save` consumes this documented browser-supported byte representation, not decoded fact JSON. Any normalized byte representation needs an explicitly implemented and validated browser profile. A JSON snapshot/status API for facts/freshness is a separate explicit extension; it is not included in this runtime or starter. Fixed-file adapters watch the parent directory and periodically rescan. Latest-slot adapters inspect supported card/slot metadata and choose the latest eligible slot using documented timestamp/tie rules, ignoring temporary/unrelated files. Malformed new candidates retain the last good supported bytes; any source-selection error/freshness reporting uses a separately specified interface. Mount directories rather than single-file `subPath` mounts so atomic sync replacement remains visible. Output lives separately from synchronized inputs; tests never edit saves, restore/rescan sync, or restart production to manufacture results.
