# Evidence matrix form

Use one row per claim or fixture. Store real saves and account observations outside the public tree. A public fixture may be synthetic only when its origin and expectations are attributable independently of the production decoder.

| Claim/field or scenario | Source URL/revision/date | Fixture origin (constructed, edited/community, owned other-core, owned target-core) | Game/edition/core/version/profile | Capture time / private fixture hash and metadata reference | Expected facts / independent oracle and its origin | Validation (source, synthetic, genuine target-runtime) | Result (pass, fail, skipped, unknown) / limit |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

An oracle may be a documented format example, independently reviewed generator/specification, or logged in-game observations from a genuine capture. Expected values copied from production parser output are circular. File length, offset guesses, trimming/padding and other-core similarity do not identify a supported profile; document headers, slot structure, endianness/compression/checksums first.

| Achievement ID / main or challenge membership | Independent published IDs/counts evidence | Executable condition source/semantics (or unknown hash) | Guide assistance validated | Actual intended-core gameplay / confirmed hardcore award time and source (or open) |
|---|---|---|---|---|
| | | | | |

Keep manual checklist state, observed save facts, softcore awards and confirmed hardcore awards in separate fields. Preserve the service's real fetched time during cached failures; unavailable progress differs from an empty award list.
